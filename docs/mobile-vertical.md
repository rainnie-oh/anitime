- `src/vertical/VerticalTimeline.jsx`、`vertical.css`、`use-vertical-layout.js`；`Public.jsx` 按断点选择纵向或横向布局，两者通过同一个位置 ref 交接年份、地区和模式。

- 状态没有抽成共用的 `useTimelineState` hook。两种布局之间只交接年份、地区和模式；横竖切换时，打开的详情和系列聚焦会关闭。

- 首屏停在 1868；切换参照栏或地区标签后年份不变。
- 系列聚焦：其他地区的标签禁用、参照栏变淡；返回后滚动位置和焦点都恢复。
- 详情是底部弹出；系统返回会依次关闭详情、退出系列。
- 总览点击时期能进入正确的地区和年份。
- 320 宽没有横向滚动。
- 宽度变化以及切换到横向时，年份都能保持。

**尚未验证**：真机 iOS Safari / Android Chrome、触摸下拉关闭、`navigator.share`（测试浏览器不支持）、VoiceOver/TalkBack、系统字体放大、慢网与性能测量。

## 1. 要解决的问题

- 桌面版是横向时间线：年份尺沿 X 轴排开，一次展开一个地区，其他地区只显示紧凑封面；密集时期在固定高度的集合里纵向滚动。这套结构依赖“横向滑动看年代，纵向滚轮看集合”两条轴，在手机上会冲突：页面纵向滚动、集合纵向滚动、时间线横向拖动三者叠在一起，很难区分。
- 6.1 的决定：窄屏不再压缩横向布局，改成**纵向时间轴**，年代从上到下排列，纵向滚动就是沿时间前进。只换布局和输入方式，数据、日期规则、详情、系列聚焦、分享都不另做一套。
- 当前目录：3 个地区、27 个时期、77 部作品。分布很不均：日本 47 部（平成一个时期就有 18 部），欧美 24 部，中国 9 部。4 个系列（JoJo 7 部、Fate 7 部、怪化猫 5 部、咒术回战 2 部）。纵向方案必须应付“平成很长，中国很稀”这种差异。

## 2. 三个方向共用的基础

以下规则不随方向改变；第 3 节只写各方向的差异。

### 2.1 模块边界：不分叉内容逻辑

```
src/Multitrack.jsx            桌面横向（不改布局）
src/vertical/VerticalTimeline.jsx  新增：纵向布局与触摸输入
src/vertical/vertical.css          新增：只使用 typography.css 的 token
src/timeline-state.mjs / useTimelineState  从 Multitrack 抽出：mode、focus、seriesId、selected、
                                     beforeSeries（返回上下文）——两种方向共用
src/multitrack.mjs            继续提供 periodGroups、workCollections 等；新增纯函数
                              makeVerticalScale（见 2.3），和 makeScale 并列，并补测试
共用不改：catalog.json / 内容 API、date.mjs(formatDate)、series.mjs(filterSeries)、
          series-stacks.mjs(stackSeries/stackPreview)、WorkDetail.jsx、share-button.jsx、
          progressive-cover.jsx、segmented-control-tabs.jsx、motion.mjs
```

- 入口层 `Public.jsx` 用一个 `useTimelineOrientation()`（matchMedia）决定渲染 `Multitrack` 还是 `VerticalTimeline`。不靠 UA 判断。
- **浏览位置用“锚点年份”保存，不存像素。** 桌面现在存 `scrollLeft`。改为两种方向都存“视口起点所对应的年份 + 当前时期 id”，这样横竖屏切换、窗口缩放、切换地区、系列返回都能回到同一个年代。现有的 `beforeSeries.left/top` 再加一个 `anchorYear` 字段即可，桌面行为不变。

### 2.2 屏幕骨架（所有方向一致）

```
┌──────────────────────────────┐
│ ANITIME              ⤴ 分享 │ 48px   顶栏：字标左、分享右（同桌面）
│ [總覽|時間線]   日本 歐美 中國 │ 44px   视图切换 + 地区标签（44px 触控高度）
│ 1868  明治                    │ 56px   当前年份（--text-display 42px 红色）+ 当前时期
│       日本 · 1868—1912        │        系列聚焦时这一行换成「‹ 返回全部作品 / X系列」
├────┬─────────────────────────┤
│1868┤ ■ 明治                  │        左侧 52px 年份脊：时期边界刻度，12px 等宽数字；
│    │  ┌────┐ ┌────┐         │        离视口顶部最近的刻度变红、放大（沿用桌面
│    │  │    │ │    │  …      │        “最近刻度红色强调”的规则）
│1900┤  └────┘ └────┘         │
```

- 顶部三行共 148px，是 sticky 的。iPhone SE（667 高）上可用内容约 520px。实现时可以加“向下滚动时收起第一行，向上滚动时露出”，原型里没有做。
- 桌面底栏的前后箭头和进度条在移动端去掉，因为纵向滚动本身就是进度。署名「Made by Rainnie with ❤️」放在内容末尾，占正常布局空间。
- 字号全部用现有 token：卡片标题 12/600，日期 12，时期 14/600，操作 13（≤700px），正文 16/1.8，当前年份 42/700。颜色只用黑、白、`--ink-secondary`、`--ink-accent`。不新增字号，长时期名不靠缩字解决，改用换行或竖排。

### 2.3 纵向比例尺 `makeVerticalScale`

做法和 `makeScale` 相同，只是轴向转了 90°：

1. 刻度取时期边界（从最早有作品的时期开始，空的更早时段不显示，同桌面）。
2. 相邻刻度的基础间距为 `clamp(年数 × k, 40px, 300px)`。和桌面一样，不说成严格等比例。
3. **按内容保留高度**：同一地区里重叠的时期先合并成一个集合（同 `workCollections`），再算出集合需要的高度（时期标题 52 + 各行卡片高度 + 间距）。如果两个刻度之间放不下，就把缺的高度线性分摊到后面的刻度上（同 `makeScale` 的 `missing` 分摊）。
4. 哪些地区参与“保留高度”由方向决定（A/C：只有当前展开地区；B：所有列）。所以切换地区会重新排版，再用锚点年份把视口恢复到同一年。桌面“切换地区保持横向年代位置”这条规则，在纵向下变成“保持年份”。
5. 系列聚焦时使用压缩版本（同 `makeSeriesScale`）：只保留系列涉及的刻度，间距取最小值，再按卡片需要的高度撑开。
6. 「年代待定」组放在最后一个刻度之后，标注「位置不代表史實年份」。推断年代仍由 `formatDate` 生成「約…」「…世紀」，不会伪造确切年份。

**不使用嵌套滚动。** 桌面的“密集集合在固定高度里独立滚动 + 底部淡出”在手机上会把页面滚动困住，所以纵向模块让集合完全展开、撑开时间轴。底部淡出提示在纵向下不需要。这一点和桌面 4.1 的集合规则有意不同，需要在 PRD 6.1 里写清楚。

### 2.4 总览（三个方向相同）

```
┌────┬─────────┬─────────┬─────────┐
│    │ 日本     │ 歐美     │ 中國     │  列头 sticky
│前221┤         │         │■ 秦代 1 │
│ 184┤         │         │■ 漢末・三│
│    │         │         │  國 1    │  长名换行，不缩字
│ 793┤         │■ 維京時代1│         │
│ 794┤■ 平安 2 │         │         │
│1185┤■ 鎌倉・南│         │         │
│    │  北朝 2  │         │         │
```

- 桌面总览是“每个地区一行，时期沿共享横轴排开”；纵向就是“每个地区一列，时期沿共享纵轴排开”。每列约 (宽 − 52) / 3 ≈ 112px（390 宽时）。
- 坐标是压缩的共享坐标：每个刻度只往下移到所有地区的标签都能完整放下为止（等于把 `makeOverviewLayout` 的“量宽度”换成“量高度”）。保留方形标记、数量徽标（0 圆角）、细竖线表示时期跨度。
- 点击时期：进入时间线，展开该地区，滚动到该时期顶部（等于桌面的 `enter()`）。点击地区标签：进入时间线，回到离开总览时的年份。
- 悬停效果换成按下（`:active`）的安静反馈：红色文字和标记，不铺红底。

### 2.5 系列聚焦与返回

- 入口：海报堆叠（同地区、同时期、同系列 ≥2 部，最多叠 3 张，角度 −5°/−2°/+4°），或详情里的「X系列 ↗」。**移动端去掉卡片下方的系列链接**：44px 高的链接放在每张卡片下面会太挤，堆叠和详情已经能进入系列。
- 进入时保存 `{anchorYear, scrollTop, focus, mode, opener}`，切换到压缩比例尺并滚动到顶部，焦点移到返回按钮。
- 第三行变成唯一的返回入口：「‹ 返回全部作品 / 怪化貓系列」，sticky，44px 触控高度（对应桌面“展开地区标题旁只保留一个返回”）。系列里没有作品的地区：标签禁用，并按方向弱化显示（见第 3 节）。
- 返回：恢复模式、地区、滚动位置，并把焦点还给原来的堆叠或卡片（用 `data-stack-key` 找回，和桌面一样）。原型已验证：返回后 scrollTop 与进入前相同，焦点回到「展開怪化貓系列」堆叠。
- Android 的返回键、iOS 的边缘返回手势：建议进入系列时 `history.pushState` 一条不含参数的状态，`popstate` 时调用 `clearSeries()`。这样不会改变分享地址（分享仍然去掉查询参数和锚点）。

### 2.6 作品详情

- 复用 `WorkDetail.jsx` 的模板和内容顺序：封面、标题、红线、年代（24px）、版本、原名、地区·时期·媒介、系列入口、简介 16/1.8、「訪問官網」黑色按钮。只加一层移动端 CSS：`<dialog>` 从底部滑出，几乎占满全屏（顶部留 24px 露出时间线，让人知道还在原页面），顶部有拖动条。
- 关闭方式：× 按钮（44×44）、点遮罩、Esc，在详情滚动到顶部时下拉超过 90px 也会关闭；系统返回手势的处理同 2.5。关闭后焦点回到触发的卡片（PRD 4.2）。
- 减少动态效果时取消滑入动画，直接显示。

### 2.7 分享

- 位置和文案不变：顶栏右侧「分享」+ Remix 图标，下拉菜单依次为「複製連結」「分享到 X」，复制成功或失败都有反馈。菜单项高 44px。
- 可选增强（待确认）：支持 `navigator.share` 时增加第三项「更多…」调用系统分享面板。不替换现有两项，保持 4.4 的顺序和能力范围。分享内容仍然只是页面地址。

### 2.8 断点、方向切换与目标设备

| 条件 | 布局 |
| --- | --- |
| 视口宽度 < 768px | 纵向模块 |
| 横屏手机：`(max-height: 500px) and (pointer: coarse)` | 纵向模块（列更宽，更好读） |
| ≥ 768px（iPad 竖屏 768/820 及以上） | 桌面横向（已有 ≤1050px 的顶栏换行规则） |

- 横竖布局切换时以锚点年份交接，打开的详情和系列状态保留（状态在共用的 hook 里）。
- 现有 ≤700px 的“窄屏横向”样式在纵向模块上线后删除；在那之前它只是过渡状态。
- 设计和检查的宽度：**360**（Android 基准）、**375×667**（iPhone SE，最矮）、**390×844**（iPhone 13–16 主力）、**430×932**（Pro Max）。320px 只要求不破版。
- 验收真机（建议）：一台 iPhone，iOS Safari，含 SE 级矮屏；一台 Android，Chrome，360 宽。另外测减少动态效果、系统字体放大 130%、慢速 4G。

### 2.9 触摸手势

- 只用原生纵向滚动。不 `preventDefault` 纵向手势，不劫持滚动，不做 scroll-snap（作品高度不一，吸附会很跳）。
- 点击：卡片打开详情；堆叠进入系列；时期标题、参照、同期标签切换地区。所有可点区域至少 44×44（视觉可以更小，靠 padding 扩大）。
- 不拦截双指缩放（保留浏览器缩放，便于无障碍）。
- 横向滑动只有方向 A 会用到（切换地区），而且起点必须离屏幕边缘超过 24px，避免和 iOS 边缘返回冲突。
- 卡片按下时给 `:active` 反馈（不使用位移动效）。

### 2.10 性能

- 封面继续用 `ProgressiveCover`：A、C 两列卡片在 2x 屏上约 160px 宽，用 328w 变体；B 的紧凑缩略图用 80w。保留内联预览和按视口加载。
- 77 部作品全部渲染 DOM 没有压力。目录增长到几百部时，按时期集合做视口外不挂载（content-visibility 或 IntersectionObserver），这一条先不做。
- 滚动监听用 passive 方式，只更新当前年份和刻度高亮的 class，不重新排版。

## 3. 三个布局方向

下面的“滚动长度”是原型在 390 宽时的实测内容高度，不含顶部 sticky 区域（可视内容约 670px）。

### 方向 A：地区分页（标签切换）

```
┌──────────────────────────────┐
│ [總覽|時間線]   日本 歐美 中國 │
│ 1910  明治                    │
├────┬─────────────────────────┤
│1912┤ ■ 大正                   │
│    │ 1912—1926                │
│    │ [同期 歐美 戰間期 5][同期 中國 民國 1] ← 横向可滑的同期标签
│    │ ┌──────┐ ┌──────┐        │
│    │ │鬼滅  │ │大正處女│        │  两列海报，每张约 155px 宽
│    │ └──────┘ └──────┘        │
│1926┤ ■ 昭和 …                 │
```

- **多地区对照**：一次只显示一个地区（全宽两列）。同时性靠每个时期标题下的「同期」标签来提示：列出其他地区在这段时间有作品的时期和数量；点一下就切到那个地区，并停在重叠的年份。左右滑动也可以切换地区，年份不变。
- **总览**：用 2.4 的三列总览，是唯一能同时看到三个地区的地方。
- **系列聚焦**：其他地区的标签禁用，「同期」标签只在系列范围内计算。
- **详情和分享**：同第 2 节。
- 优点：实现最简单，两列海报最舒展；和桌面“地区标签”的心智一致。
- 缺点：时间线页面里看不到其他地区，“同时性”降成一行文字标签；切换地区等于翻页，容易迷失在哪个地区。
- 滚动长度：日本 7661px（约 11 屏），欧美 5811，中国 4631。

### 方向 B：地区并列窄列（桌面的直接转置）

```
┌──────────────────────────────┐
│ 1906  明治                    │
├────┬──────────────┬────┬────┤
│    │ 日本          │歐美│中國 │ ← 列头 sticky，展开列为红色
│1912┤ ■ 大正        │    │ ■  │
│    │ ┌──────────┐ │    │ 民 │  紧凑列：时期名竖排 +
│    │ │ 鬼滅之刃  │ │    │ 國 │  最多 4 张 44×30 缩略图，余下显示 +N
│    │ │          │ │    │[▭] │
│    │ └──────────┘ │    │    │
│1918┤               │ ■戰│    │
```

- **多地区对照**：三列共享同一个纵轴，和桌面一样“一个展开，其他紧凑”，同一高度就是同一年代。点击紧凑列里的某个时期，就展开那个地区并停在该时期。展开列在原位置变宽，列的顺序固定为 日本/歐美/中國，用户不用重新找列的位置。
- **总览**：同 2.4。时间线本身已经有三列，所以总览和时间线的空间关系最一致。
- **系列聚焦**：没有该系列作品的列变淡、轻微模糊，并且不能点击（对应桌面“无关地区保留为模糊、淡化的背景参照”）。
- 优点：最忠实于桌面模型，紧凑封面让人一眼看到其他地区“这里也有作品”。
- 缺点：展开列在 390 宽时只有约 200px，在 360 宽时约 170px，只能单列放海报，所以页面很长：日本 13033px（约 19 屏），是 C 的两倍。三列都参与保留高度，稀疏地区会出现大段空白列。紧凑缩略图只有 44px 宽，几乎认不出作品。
- 滚动长度：日本 13033，欧美 7735，中国 5749。

### 方向 C：主地区 + 侧边参照栏（推荐）

```
┌──────────────────────────────┐
│ 1910  明治                    │
├────┬────────────────────┬─┬─┤
```

- **多地区对照**：展开地区用两列海报（390 宽时每张约 140px）。右侧 68px 的参照栏放另外两个地区，用**同一个纵向比例尺**画出它们的时期跨度、竖排时期名和作品数。所以和桌面一样，“同一高度就是同一年代”，但参照栏只占 1/6 宽度。点参照栏的任意时期，就展开那个地区，并停在当前年份（如果当前年份落在该时期内）或该时期的开头。
- 繁体中文竖排是这个方向的视觉特色：窄道里的时期名用 `writing-mode: vertical-rl`，不用缩小字号，也不用截断。
- **总览**：同 2.4。参照栏可以看成“总览在时间线里的缩影”。
- **系列聚焦**：参照栏里没有该系列作品的地区变淡、模糊；地区标签禁用。
- 优点：在可读性（两列海报、滚动最短）和同时性（始终看得到另外两个地区的年代分布和数量）之间取得了最好的平衡；比例尺只由展开地区决定，不会因为别的地区密集而留下空白。
- 缺点：参照栏只有文字，看不到其他地区的封面；只靠竖线表示“同时”，比 B 抽象。参照栏的点击区域比较窄（28px 宽），需要把整段时期跨度都设为可点，并保证每段至少 44px 高（原型里已经这样做）。同一地区里重叠的时期（欧美 中世紀晚期 1337–1487 和 文藝復興 1400–1600）在窄道里需要错开显示，原型还没处理。
- 滚动长度：日本 6623，欧美 5162，中国 4254。

## 4. 推荐

**推荐方向 C（主地区 + 侧边参照栏）**，同时吸收 A 的「同期」标签作为可选补充。

理由：PRD 把“不同地区的同时性”放在产品定位的第一句，A 在时间线里把它弱化成文字标签；B 最忠实于桌面，但在 360–390 宽时只能单列放海报，日本时间线长达约 19 屏，紧凑缩略图也认不出作品，代价太大。C 保留“一个展开、其他紧凑参照”的结构和共享纵轴，展开地区仍有两列海报，滚动最短，竖排时期名也让黑白红的编辑感在手机上有自己的样子。

如果用户更看重“看到其他地区的封面”，可以选 B，或者在 C 的参照栏里给当前视口内的时期加 1 张 28px 缩略图（需要再验证可读性）。

## 7. 原型说明与验证范围

- 原型为了能独立打开，复制了 `periodGroups`、`formatDate`、`stackSeries`、`filterSeries` 的逻辑。正式实现必须直接 import `src/` 里的模块，不能保留这份复制。原型的海报堆叠没有区分重叠时期，横向滑动切换地区（A）、隐藏顶栏、history 返回都没有实现。
- 在内置浏览器里检查过（390 和 360 宽的手机框）：三个方向都能渲染；地区切换、方向切换、宽度切换后年份保持不变；总览点击时期能进入对应时期；进入怪化猫系列后其他地区被禁用，返回后滚动位置和焦点都恢复；详情底部弹出能打开和关闭；控制台没有错误。
- 没有在真机上测试，没有测触摸手势（下拉关闭只写了代码），没有做 VoiceOver/TalkBack、系统字体放大和性能测量。以上都不能算已验收。
