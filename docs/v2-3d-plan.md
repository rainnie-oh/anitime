# ANITIME 2.0 · 3D 时间线规划

更新：2026-10-17。分支 `feature/v2-3d`，基于 `origin/feature/multitrack-view` 760fcce（含移动端纵向模块）。工作目录 `Anitime/v2-3d/`。

## 1. 目标

把桌面时间线从 2D 平面改为 3D 场景：**地面是历史时间线**，**作品卡片垂直立起、悬浮在地面上方**。参考图上半是 Overview（整段历史压成一列"书架"），下半是聚焦某个时期（卡片沿时间轴展开，选中卡片被抽出）。

不变：数据模型、结构化日期规则、作品详情 `WorkDetail`、CMS、分享、移动端纵向模块。

## 2. 视觉语言（从参考图提取）

| 元素 | 参考图 | ANITIME 2.0 |
| --- | --- | --- |
| 镜头 | 等轴测（正交、无透视），时间轴沿左下→右上对角线 | 同。正交投影保证同一年份在各处尺寸一致，符合"共享年份坐标" |
| 地面 | 浅灰白、接近无限的平面，刻度线平躺在地面 | 白色地面；年份刻度、时期色带和时期名**平躺在地面上** |
| 卡片 | 竖立的薄片，侧面朝镜头，密集排列 | 海报竖立在故事年代位置，有轻微投影；Overview 中只露出侧面和一点画面 |
| 聚焦 | 当前位置两侧卡片拉开，选中卡片单独悬浮并带 ⊕ | 同。⊕ 打开现有作品详情 |
| 左上 | 日期 + 时间 | 当前时期名 + 年份（沿用现有的红色重点年份） |
| 正上 | `every : second`（粒度） | 视图切换 總覽 / 時間線（现有分段控件）+ 地区 |
| 右侧 | 标签列表 + 数量上标 | 待定，见第 6 节 |

黑白红保留：地面与卡片是黑白灰，红色只用于当前年份、当前时期标记和选中状态。

## 3. 两种视图

### 3.1 Overview（参考图上）
- 整个历史跨度压成一列：所有作品按故事年代排在对角线上，卡片几乎侧面朝前，形成"书架"。
- 地面上显示时期色带与名称 + 少量年份刻度。
- 悬停一段，卡片轻微抬起并显示时期名与数量；点击进入该时期的聚焦视图（对应现有"点时期进入时间线"）。

### 3.2 聚焦（参考图下）
- 镜头推近并沿时间轴平移到所选时期。
- **手风琴式展开**：当前位置附近的卡片拉开间距并转向镜头，越远越密，回到书架状态。
- 滚轮 / 触控板 / ← → 键沿时间轴移动"当前位置"，展开区随之移动；左上年份实时更新。
- 选中卡片被抽出并上浮，显示名称、年代和 ⊕；⊕ 或回车打开 `WorkDetail`。
- 系列：同系列卡片一起抬起，其他卡片变淡，作为系列聚焦的 3D 版本。

### 3.3 多地区（需要决定）
- **推荐 A：三条平行轨道**。日本、欧美、中国是地面上三条平行的书架，共用同一时间轴（x = 年份）。当前地区在前排、清楚；其他地区在后排、变淡。和现有"一个地区展开、其他保持紧凑"的逻辑一致，"同时性"在 3D 里最直观。
- B：一条轨道，切换地区时整条换内容。更接近参考图，但失去跨地区对照。

## 4. 技术方案

### 4.1 渲染：先用 CSS 3D，规划可退回到 Three.js
- **推荐 CSS 3D transforms**（`transform-style: preserve-3d`，正交 = 不设 `perspective`）。
  - 目前 77 部作品，未来几百部，DOM 撑得住。
  - 文字清楚、可访问性好、键盘焦点是天然的；能直接复用 `ProgressiveCover`、`WorkDetail`、分享和分段控件。
  - 不增加依赖。
- Three.js / react-three-fiber 作为后备：如果需要真实阴影、上千张卡片或自由镜头，再迁移。代价是包体积大约多 150KB+，文字和焦点都要自己实现。
- **第 1 阶段的探针负责验证这个选择**，用真实 77 张封面测帧率和图片内存，不靠猜测。

### 4.2 场景结构
```
<Scene3D>                     镜头容器：rotateX(60°) rotateZ(-45°)，scale/translate 实现推近与平移
  <Ground>                    地面平面：时期色带、年份刻度、时期名（平躺）
  <Rail region="日本">        每个地区一条轨道（方案 A）
    <Card3D work=…>           rotateX(-90°) 立起；translateX = 年份坐标；展开时 rotateY 朝向镜头
```
- 坐标复用现有纯函数：`makeScale` / `periodGroups` / `workCollections`（`src/multitrack.mjs`），`stackSeries`（系列），`dateOrder` / `formatDate`（日期）。3D 只新增"年份坐标 → 3D 位置"和"手风琴展开"两个纯函数，放在 `src/scene3d.mjs`，用 node:test 测试。
- 镜头状态（`center`, `zoom`）是唯一的动画源；Overview ↔ 聚焦只是镜头插值，卡片间距由 `center` 计算得出。

### 4.3 入口
- 和现有模式一样，在 `Public.jsx` 里分流：桌面在 2.0 分支默认使用 `Scene3D`；`?view=2d` 保留现有 Multitrack 以便对照；窄屏继续用纵向模块。
- 通过 `position` ref 共享年份 / 地区，切换视图时不丢失浏览位置（纵向模块已有这个机制）。

### 4.4 性能预算（探针阶段确认）
- 目标：在中端笔记本上，聚焦平移 ≥ 50fps，Overview 静止时不持续占用 GPU。
- Overview 卡片使用 80px 变体，聚焦展开区附近使用 328/656px，按镜头位置决定加载。
- 合成层：只给展开区内的卡片加 `will-change`；其余卡片作为普通 3D 平面。
- 减少动态效果：关掉镜头插值和手风琴动画，直接跳到目标状态；必要时退回 2D Multitrack。

## 8. 阶段 1 探针结果（2026-10-17）

- 实现：`src/scene3d.mjs`（坐标轴、轨道、地面刻度、手风琴透镜，5 项测试）、`src/scene3d/Scene3D.jsx` + `scene3d.css`（CSS 3D 正交场景）。桌面默认进入 3D，`?view=2d` 回到 1.x 多轨道，窄屏仍是纵向模块。
- 已有：三条平行轨道（当前地区在前排）、Overview 全景书架、点时期 / 卡片进入聚焦、滚轮与 ← → 沿时间移动、Esc 回总览、手风琴展开 + 选中卡片抬起并显示 ⊕、左上地区·时期·年代与作品名、右下时期索引（作品数）、作品详情沿用 `WorkDetail`。地面文字按缩放反向放大，屏幕字号保持不变。
- 性能（Chrome，1440×900，77 张卡片）：每次滚轮更新的主线程耗时中位数 7.4ms，p95 12.8ms，最差 30ms；77 张封面使用 164px 变体全部加载，JS 堆约 29MB。由于预览面板被隐藏，帧率测量被浏览器限流，**合成帧率尚未实测**，需要在前台窗口复测。
- 初步结论：CSS 3D 可以达到参考图的效果，暂时不需要 Three.js。
- 已知问题：总览中较短时期的名称会重叠或被卡片遮挡；滚轮驱动的 0.6s 过渡会让滚动有拖尾感；后排轨道在聚焦时可读性较弱；系列堆叠、入场动效、减少动态效果的完整处理尚未接入。
